Express
   - Node.js 환경에서 동작하는 가장 대중적이고 가벼운 웹 프레임워크로, 
   복잡한 설정 없이도 웹 애플리케이션의 기본 구조를 빠르게 완성할 수 있습니다.
   직관적인 라우팅 시스템을 통해 다양한 HTTP 요청과 경로를 손쉽게 관리하며, 
   강력하고 효율적인 API 서버를 구축할 수 있도록 지원합니다. 유연한 미들웨어 구조를 바탕으로
   인증, 로깅, 에러 처리 등 필요한 기능을 자유롭게 추가하고 확장하여 견고한 서버 로직을 구현할 수 있습니다.

[express 설치 명령어] 
> yarn add express cors

[제 코드를 받으시면]
> yarn install

REST API(Representaional State Transfer API)
   HTTP URI(Uniform Resource Identifier)를 통해 자원을 명시할 수 있어야 한다.
   HTTP Method(GET, POST, PUT, PATCH, DELETE 등)를 통해 해당 자원에 대한
   CRUD를 적용한다.

REST API 설계 방식
   1. URI는 동사가 아닌 명사, 대문자가 아닌 소문자로 사용해야 한다.
      잘못된 예시: http://app.com/Writing
      올바른 예시: http://app.com/write

   2. 마지막에 슬래시를 작성하지 않는다.
      잘못된 예시: http://app.com/api/post/1/
      올바른 예시: http://app.com/api/post/1

   3. 언더바 대신 하이폰을 작성한다.
      잘못된 예시: http://app.com/api/fruit_info
      올바른 예시: http://app.com/api/fruit-info

   4. 확장자를 포함시키지 않는다.
      잘못된 예시: http://app.com/api/fruit.png      
      올바른 예시: http://app.com/api/fruit

   5. 동작을 포함시키지 않는다.
      잘못된 예시: http://app.com/api/do-read/1
      올바른 예시: http://app.com/api/post/1

RESTful
   REST 원칙을 따르는 시스템을 의미한다.
   REST방식으로 설계했을지라도 설계 원칙 및 규칙을 정확하게 지킨 시스템만이 RESTful하다고 말한다.

CORS(Cross Origin Resource Sharing)
   - origin : url에서 uri를 제외한 것이 origin이라고 한다. 하나의 로컬 서버에서는 
   origin이 동일해야 하며, 이 origin이 요청하는 것은 요청할 수 있도록 정책을 변경하여 설정해야하는데
   배포 환경에서는 달라질 수 있으므로 기본 설정해주는 방법과 브라우저에서 설정해주는 방법을 사용해서 정책을    변경할 수 있다.

Http 요청 방식
    - Create (POST): 서버에 새로운 데이터나 리소스를 생성(추가)할 때 사용하는 요청 방식입니다.
   - Read (GET): 서버에 저장된 데이터를 조회(읽기)할 때 사용하는 요청 방식입니다.
   - Update (PUT): 서버에 존재하는 기존 데이터를 전체 수정하거나 덮어쓸 때 사용하는 요청 방식입니다.
   - Delete (DELETE): 서버에 존재하는 특정 데이터나 리소스를 삭제할 때 사용하는 요청 방식입니다.
